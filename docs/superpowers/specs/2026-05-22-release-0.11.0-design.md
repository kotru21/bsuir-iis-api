# Release 0.11.0 Documentation Design

## Goal
Update release documentation and versioning for 0.11.0 based on changes since commit 5dff629ed63a62dfb6febe4516817acf5c4c4215, then run build and API report to keep generated artifacts in sync.

## Context
The release is published via GitHub Actions to npm. The release notes must include all user-facing changes and any internal changes that are significant for behavior, compatibility, or release quality.

## Scope
In scope:
- Update CHANGELOG for 0.11.0 with a 2026-05-22 date.
- Update README to reflect public API and behavior changes since 0.10.1.
- Bump version to 0.11.0 in package.json and package-lock.json.
- Run build and api report to refresh generated outputs.

Out of scope:
- New feature development or refactors beyond documenting existing changes.

## Inputs
- Git range: 5dff629ed63a62dfb6febe4516817acf5c4c4215..HEAD.
- Changed files list with emphasis on src/client, src/modules, src/helpers, src/utils, README, CHANGELOG, examples, and tooling configs.

## Approach (File-Driven)
1. Review changed files and map changes into user-facing vs internal-important buckets.
2. Draft CHANGELOG 0.11.0 entries grouped by section: Added, Changed, Fixed, Documentation, and Potentially Breaking (only if applicable).
3. Update README sections affected by public API changes and behavior changes.
4. Bump version to 0.11.0 and keep lockfile consistent.
5. Run build and api report; reconcile updates in etc/bsuir-iis-api.api.md and any tracked temp API report outputs.

## Changelog Classification Rules
- User-facing: new exports, new options, changed defaults, error behavior, schedule raw/normalized behavior, and validation rules.
- Internal-important: major HTTP pipeline restructuring, caching semantics, signal merge behavior, response validation flow, and test coverage gates.
- Tooling: dependency upgrades or config changes that materially affect contributors or CI.
- Exclusions: pure test additions unless they enforce new behavior or coverage gates.

## README Update Targets
- Client options and their runtime behavior changes.
- Public exports (helpers, types, and modules) added or changed.
- Schedule raw vs normalized behavior changes and subgroup overload clarifications.
- Errors and validation rules that changed or are newly documented.

## Release Steps
- Apply doc updates and version bump.
- Run: npm run build.
- Run: npm run api:report.
- Ensure tracked API report outputs are updated and no build artifacts are left untracked.

## Verification
- Build succeeds (tsup).
- API report generation succeeds and outputs are consistent with updated public surface.

## Risks and Mitigations
- Risk: missing a user-facing change hidden in refactors. Mitigation: file-driven review plus README scan.
- Risk: API report drift. Mitigation: run api:report and update tracked outputs.
